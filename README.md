# Jio Subscriber Churn Intelligence & Revenue Protection

An end-to-end churn analytics project for a telecom subscriber base: exploratory data analysis,
predictive modeling (XGBoost champion vs. Logistic Regression baseline vs. Random Forest), a SQLite
database layer, and an interactive Streamlit executive application with a SQL-grounded conversational
assistant.

## What's inside

| Area | Description |
|---|---|
| **Data** | 64,738 synthetic Jio subscribers (43 columns) plus a supplementary workbook with service requests, network sites, monthly circle KPIs, circle targets, and an offer catalogue. |
| **EDA (Workstream 1)** | Full variable-by-variable diagnostics, churn-driver correlations, circle/zone/ARPU/recharge-gap risk analysis, and auto-generated executive PDF reports. |
| **Modeling (Workstream 2)** | Three compared models (Logistic Regression baseline, Optuna-tuned XGBoost champion, Random Forest) evaluated on ROC-AUC, PR-AUC, and Recall@Top-Decile, with SHAP explainability. |
| **App (Workstream 3)** | A 3-page Streamlit app: Executive Overview, Subscriber Risk Lookup (live scoring), and a Conversational Churn Assistant that answers questions with real-time SQL against a SQLite database. |

## Headline results

- **1.73%** baseline 30-day churn rate (1,122 churned of 64,738 subscribers)
- **Champion model: XGBoost** — ROC-AUC `0.9473`, PR-AUC `0.2989`, Recall@Top-10%-Risk `87.5%`
- Strongest churn signal: MNP (portability) enquiry, followed by recharge silence and ARPU decline

```
  advanced_workstream1_report.py  Circle risk tiering + ARR exposure executive brief -> PDF

  generate_business_report_pdf.py       Client-ready EDA business brief -> PDF
  generate_executive_pdf_report.py      Executive EDA summary -> PDF
  generate_project5_executive_report.py Combined EDA + modeling executive report -> PDF
  generate_architecture_diagram.py      Renders the system architecture diagram
  app.py                          The Streamlit application (entry point)
Reports/
  figures/                        Generated chart PNGs
  *.csv / *.json / *.pdf          Generated metrics, stats, and PDF reports
  xgboost_champion_bundle.joblib  Persisted champion model + preprocessor
```

## Setup

```powershell
# 1. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# 2. Install dependencies
pip install -r requirements.txt
```

## Running the pipeline

Run these once, in order, from `Python_Scripts/`, to regenerate all reports/artifacts from scratch:

```powershell
cd Python_Scripts
python comprehensive_eda.py          # EDA stats + figures
python train_churn_models.py         # Trains models, saves champion bundle + metrics
python build_database.py             # Builds Data/jio_retention.db for the app's SQL assistant
```

(The PDF report generators and `generate_architecture_diagram.py` are optional - they turn the above
artifacts into polished executive PDFs / diagrams.)

## Running the app

```powershell
cd Python_Scripts
streamlit run app.py
```

Open the printed local URL (default `http://localhost:8501`). The app has three pages:

1. **Executive Overview & Metrics** — KPI cards, model comparison table, and visual diagnostics.
2. **Subscriber Risk Lookup** — look up any `subscriber_id` for a live churn-risk score and plain-English
   explanation of why they're flagged.
3. **Conversational Churn Assistant** — ask natural-language questions; answers are fetched via live SQL
   against `jio_retention.db`, with a strict "Data not available" guardrail for anything out of scope.
   Examples:
   - `how many subscribers in Gujarat`
   - `how many are high risk and from which circle`
   - `what is the average arpu_last_month_inr`
   - `show subscribers in Gujarat`
   - `what columns does service_requests have`

## Notes

- `Data/jio_retention.db` is generated by `build_database.py` and is not tracked in git by default size
  policy for this repo — if you clone fresh, run `build_database.py` once before starting the app.
- Table/column names used by the assistant's SQL queries are always validated against the database's own
  schema (`sqlite_master` / `PRAGMA table_info`), never built directly from raw user input.
